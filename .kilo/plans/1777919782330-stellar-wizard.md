# Plan: undo local texte et correction Ctrl+X/Ctrl+V

## Contexte observe
- Les champs editables rythmo utilisent `TextInputState` dans `src/ui/text_input.rs` pour les noms de personnage, textes de ligne et notes.
- Les raccourcis en edition texte sont branches dans `src/main.rs` quand `state.is_editing_text()` est vrai.
- `Ctrl+C` et `Ctrl+X` dispatchent respectivement `UiEvent::Copy` et `UiEvent::Cut` vers `src/ui/rythmo.rs`.
- `Ctrl+V` colle via `UiEvent::KeyInput { text }`, donc il emprunte la logique d'insertion existante de `TextInputState::handle_key`.
- `Ctrl+Z` global existe hors edition texte, mais aucun raccourci undo n'est traite dans le bloc `state.is_editing_text()`.
- Le bug `Ctrl+X` puis `Ctrl+V` vient de `handle_cut`: il calcule le texte selectionne, appelle `handle_key(delete, ...)`, puis retourne immediatement une action d'update. L'action `SetClipboard(text)` n'est donc pas emise quand la suppression reussit.

## Objectifs
- Dans n'importe quel champ texte editable gere par `TextInputState`, `Ctrl+Z` annule les modifications locales: frappe, suppression, remplacement de selection, collage.
- `Ctrl+X` doit a la fois copier la selection dans le presse-papiers et supprimer la selection, afin que `Ctrl+V` puisse recoller ce texte.
- Conserver le comportement existant de `Ctrl+C`, `Ctrl+V`, `Ctrl+A`, navigation au clavier, autocomplete personnage et historique global hors edition.

## Implementation prevue
1. Etendre `src/ui/text_input.rs`:
   - Ajouter un petit historique local a `TextInputState`, par exemple `undo_stack: Vec<TextEditSnapshot>`.
   - Stocker dans chaque snapshot au minimum le texte precedent, la position du curseur precedente et la selection precedente.
   - Initialiser/vider l'historique dans `new`, `activate`, `deactivate` et `set_text_external` pour eviter d'annuler dans un autre champ ou sur une valeur externe.
   - Avant toute mutation de texte dans `handle_key` qui retourne `Changed`, pousser un snapshot de l'etat courant.
   - Ajouter une methode `undo(&mut self, current_text: &str) -> Option<String>` qui restaure le dernier snapshot, remet curseur/selection/blink et retourne le texte restaure.
   - Optionnel mais prudent: limiter la pile a une taille raisonnable (ex: 100 entrees) pour eviter une croissance illimitee.

2. Ajouter l'evenement UI d'undo texte:
   - Ajouter `UndoTextEdit` ou `Undo` a `UiEvent` dans `src/ui/widget.rs`.
   - Dans `src/main.rs`, dans le bloc `state.is_editing_text()`, intercepter `Ctrl+Z` avant les touches normales et dispatcher ce nouvel evenement.
   - Garder le `Ctrl+Z` global existant uniquement hors edition texte.

3. Brancher l'undo dans `src/ui/rythmo.rs`:
   - Ajouter un handler `handle_text_undo(ctx, state)`.
   - Selon le champ actif (`editing_note`, `editing_character`, `editing_line`), appeler `note_input.undo(&line.note)`, `char_input.undo(&line.character_name)` ou `line_input.undo(&line.text)`.
   - Convertir le texte restaure en action existante: `UpdateLineNote`, `UpdateCharacterName` ou `UpdateLineText`.
   - Pour le nom de personnage, remettre `autocomplete_index = Some(0)` comme lors d'une saisie normale.

4. Corriger `Ctrl+X` atomiquement:
   - Ajouter une action UI combinant presse-papiers et modification, par exemple `SetClipboardAndUpdateLineText`, `SetClipboardAndUpdateCharacterName`, `SetClipboardAndUpdateLineNote`, ou une action generique si le style du projet s'y prete.
   - Modifier `handle_cut` pour retourner cette action combinee quand une selection existe et que la suppression reussit.
   - Dans `main.rs::handle_action`, traiter l'action combinee en appelant d'abord `clipboard_set(&text)`, puis la mise a jour correspondante (`state.update_line_text`, `state.update_character_name`, `state.update_line_note`).
   - Ainsi `Ctrl+X` mettra bien le presse-papiers a jour tout en conservant l'update undoable existante.

## Verification prevue
- Lancer `cargo test` si des tests existent et compilent rapidement.
- Lancer `cargo check` pour verifier les changements Rust.
- Verifier manuellement les scenarios cles par lecture/raisonnement:
  - champ texte de ligne: taper, coller, backspace/delete, selection+remplacement, puis `Ctrl+Z` restaure l'etat precedent.
  - nom de personnage: `Ctrl+Z` restaure le nom et garde l'autocomplete coherent.
  - note: meme comportement si consideree comme texte editable.
  - `Ctrl+X`, puis `Ctrl+V`, dans un champ editable remet bien le texte coupe.
  - hors edition texte, `Ctrl+Z` continue d'appeler l'undo global.

## Risques et choix
- L'undo local sera par operation de saisie/paste/delete, pas forcement par mot ou par session complete. Cela correspond a la demande d'annuler ce qui vient d'etre ecrit, supprime ou colle.
- Les updates texte actuelles sont coalescees dans l'historique global. L'undo local modifiera le texte via les memes actions, donc il restera compatible avec la mecanique de sauvegarde/dirty/network existante.
