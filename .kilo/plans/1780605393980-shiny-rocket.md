# Plan: Optimisation UI et export GPU

## Objectif
Réduire les coûts structurels avant les micro-optimisations:
- arrêter le redraw idle permanent,
- rendre le bouton cancel réellement interruptible,
- réutiliser les buffers GPU de l’UI au lieu de les recréer par frame,
- éviter le reshaping texte UI quand la clé de layout ne change pas,
- rendre les scans temporels sous-linéaires pour l’UI et l’export,
- supprimer au moins la copie `mapped_range -> Vec -> stdin` du chemin NV12,
- préparer ensuite le ring readback et la scène export compilée.

## Constat Vérifié
- `src/main.rs:1163` redessine puis appelle toujours `state.request_redraw()`; `src/main.rs:1182` appelle aussi toujours `state.request_redraw()` dans `AboutToWait`.
- `src/state.rs:2131` fait aussi des ticks/polls dans `render`: ping results, autosave, export completion, network, scroll decode, proxy, video tick. Le redraw infini sert donc actuellement de timer implicite.
- `src/ui/renderer.rs:640` recrée des `GlyphonBuffer` et reshape tous les labels à chaque render.
- `src/ui/renderer.rs:756` et suivants recréent plusieurs vertex buffers via `device.create_buffer_init` par frame.
- `src/ui/rythmo.rs:2469`, `src/ui/rythmo.rs:3358`, `src/ui/rythmo.rs:5359` scannent `project.lines()`/`project.markers` dans les chemins de rendu.
- `src/rythmo_gpu_renderer.rs:2087` et `src/rythmo_gpu_renderer.rs:2363` scannent toutes les lignes/marqueurs par frame export.
- `src/rythmo_gpu_renderer.rs:2647` copie le readback NV12 dans un `Vec` avant écriture ffmpeg.
- `src/main.rs:505` masque seulement la progression sur cancel, sans signaler le thread d’export.

## Non-Objectifs Immédiats
- Ne pas tenter le vrai zéro-copy Adobe-like dans cette passe. L’interop wgpu/DX12/CUDA/NVENC demanderait une refonte dédiée.
- Ne pas refondre le fallback CPU avant que les gains P0/P1/P2 soient en place.
- Ne pas ajouter `target-cpu=native` dans la config projet distribuée; le garder comme commande locale documentée.

## Étape 1: P0 Redraw Piloté Par Besoin
Fichiers principaux:
- `src/main.rs`
- `src/state.rs`
- `src/ui/mod.rs`
- `src/ui/toast.rs`
- `src/ui/text_input.rs`

Changements:
1. Extraire les ticks non-rendu de `State::render` dans une méthode dédiée, par exemple `State::tick_background() -> bool`.
2. `tick_background` doit gérer sans acquérir de surface GPU:
- résultats ping serveur,
- autosave dirty,
- sentinelle export/proxy terminée,
- `tick_network`,
- `tick_scroll_decode`,
- `poll_proxy_job`.
3. Faire retourner `true` si l’état visible a changé ou si une texture vidéo a été décodée après scroll.
4. Garder `tick_video` dans le rendu pour le chemin playback, sauf besoin explicite de tick secondaire.
5. Ajouter des helpers d’état:
- `State::needs_redraw_now()` ou `State::needs_continuous_redraw()`,
- `State::next_wake_deadline() -> Option<Instant>`,
- `Ui::needs_animation_or_interaction()`,
- `ToastManager::has_active()`.
6. Inclure dans les besoins de redraw:
- vidéo en lecture,
- export/proxy progress actif,
- toasts actifs/fade,
- drag props, scrubbing, drag BR, syllable drag, panning, ghost preview,
- édition texte/cursor blink,
- `scroll_needs_decode`,
- secondary display selon politique actuelle.
7. Dans l’event loop, remplacer le `ControlFlow` global par:
- `WaitUntil(next_deadline)` si une animation/poll périodique est nécessaire,
- `Wait` sinon.
8. Dans `WindowEvent::RedrawRequested`, faire:
```rust
state.render();
if state.needs_continuous_redraw() {
    state.request_redraw();
}
```
9. Dans `Event::AboutToWait`, faire:
```rust
let changed = state.tick_background();
if changed || state.needs_redraw_now() {
    state.request_redraw();
}
```
10. Corriger le rendu secondaire pour ne plus demander un redraw inconditionnel quand rien ne change. Pour compatibilité, garder un redraw continu si la vidéo joue ou si le secondary display doit explicitement rester animé.

Point d’attention:
- Le piège est de supprimer le redraw infini sans remplacer le polling qu’il assurait. `WaitUntil` doit réveiller l’app pendant un export/proxy, une connexion réseau active, un toast, un cursor blink ou un scroll decode différé.

## Étape 2: P0.5 Cancel Export Réel
Fichiers principaux:
- `src/main.rs`
- `src/state.rs`
- `src/video_export.rs`
- éventuellement `src/video_proxy.rs`

Changements:
1. Ajouter un token partagé:
```rust
pub struct ExportCancel {
    cancelled: AtomicBool,
}
```
ou directement `Arc<AtomicBool>` si on veut rester minimal.
2. Stocker le token dans `State`, par exemple `active_export_cancel: Option<Arc<AtomicBool>>`.
3. Au démarrage `UiAction::StartExport`, créer le token, le stocker dans `State`, et le passer au thread puis à `video_export::export_mp4`.
4. Remplacer `UiAction::CancelExport => state.set_export_progress(None)` par `state.cancel_export()`:
- met `cancelled = true`,
- garde l’overlay visible avec un label type “Annulation...” si possible,
- ne nettoie la progression que lorsque le thread signale la fin.
5. Dans `video_export.rs`, propager le token à `export_baked_mp4` et `write_br_frames`.
6. Dans `write_br_frames`, vérifier le token:
- avant chaque frame,
- avant `writer.write_all`,
- dans le fallback CPU avant de lancer ou d’écrire un batch.
7. Ajouter `StdinWriteError::cancelled()` et `is_cancelled()` avec `ErrorKind::Interrupted`.
8. Si `write_br_frames` revient annulé, tuer proprement ffmpeg:
- `child.kill()` si encore vivant,
- `child.wait()`,
- joindre les lecteurs stdout/stderr,
- supprimer ou laisser échouer proprement sans log `error` côté UI.
9. Pour `video_proxy.rs`, soit appliquer le même token en restructurant la lecture `stdout` autour de `child.try_wait()` et d’un canal de progress, soit désactiver/adapter le bouton cancel pendant un proxy jusqu’à ce que proxy ait le même mécanisme. Le comportement final souhaité est que proxy et export ne puissent plus tourner masqués en arrière-plan.

Point d’attention:
- Une seule texture offscreen et un seul storage NV12 peuvent rester suffisants parce que les command buffers sont soumis dans l’ordre et copient vers un staging distinct avant le rendu suivant.

## Validation Manuelle
- Lancer l’app sans interaction: la fenêtre ne doit plus redessiner en continu en idle.
- Vérifier qu’un toast fade correctement puis que l’app se rendort.
- Vérifier lecture vidéo: animation fluide, primary et secondary display restent synchronisés.
- Vérifier scroll/seek: le decode différé se produit après le délai et l’image se met à jour.
- Vérifier export: la progression avance encore avec redraw non permanent.
- Cliquer cancel pendant export: ffmpeg est tué, le thread termine, l’overlay disparaît après fin réelle.
- Ouvrir un gros projet: rendu BR UI et export ne doivent plus scanner tout le projet pour chaque frame visible.
- Export court GPU NV12: sortie visuelle identique, logs montrent moins de copie CPU et readback total cohérent.

## Ordre D’Implémentation Recommandé
1. P0 redraw + timers ciblés.

3. P1 buffers GPU UI persistants.
4. P1 cache texte UI.

6. P2 écriture NV12 directe.

8. P2 scène export compilée.
9. Profil release.

## Risques
- Supprimer le redraw infini sans `WaitUntil` casse les updates réseau/proxy/export parce que l’app n’est plus réveillée.
- Le cache texte UI peut afficher un layout périmé si la clé oublie la font, la taille, la largeur, l’overflow ou l’alignement.
- La révision `Project` doit couvrir les mutations via `get_line_mut`, imports, undo/redo, deltas réseau et markers, sinon l’index temporel devient stale.
- Le ring readback nécessite de préserver l’ordre d’écriture stdin; un ticket mal drainé créerait une vidéo avec frames BR désordonnées.
