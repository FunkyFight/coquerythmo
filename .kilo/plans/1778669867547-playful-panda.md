# Plan: rendu vectoriel SVG pour la police rythmo

## Objectif
Supprimer la pixellisation des textes rythmo étirés. Le texte ne doit plus être rasterisé à petite taille puis agrandi: il doit être rendu depuis une source vectorielle/SVG avec la police configurée, puis rasterisé directement à la taille finale d'affichage/export.

## Constat
- `src/ui/renderer.rs` rend les textes rythmo via `rasterize_text`, crée une texture bitmap, puis l'étire dans `prepare_stretched_texts` avec `nearest_sampler`.
- `src/rythmo_gpu_renderer.rs` fait la même chose pour l'export GPU via `get_or_upload_text`, puis dessine la texture sur une largeur finale potentiellement bien plus grande.
- `src/rythmo_cpu_renderer.rs` rasterise aussi le texte à taille naturelle, puis l'étire manuellement dans `blit_stretched_text`.
- `resvg`/`tiny-skia` sont déjà dans les dépendances, et `usvg`/`fontdb` sont déjà transitifs. Le projet a donc déjà l'infrastructure utile pour rendre du SVG.
- `glyphon` reste adapté aux textes UI classiques non étirés; le remplacement doit cibler les textes rythmo étirés pour limiter le risque.

## Approche
Créer un petit module interne de rendu texte vectoriel pour les textes rythmo:
- mesurer le texte avec la même police que maintenant, afin de garder les positions de curseur/sélection et la logique de syllabes;
- générer un SVG `<text>` utilisant `font-family` depuis `config.ui.rythmo_font` ou une famille sans-serif par défaut;
- appliquer l'étirement dans le SVG via son `viewBox`/dimensions finales, pas via un upscale bitmap;
- rendre ce SVG avec `resvg` dans une `tiny_skia::Pixmap` exactement aux dimensions finales nécessaires;
- uploader cette pixmap comme texture GPU 1:1 pour l'affichage et l'export GPU;
- blitter directement cette pixmap dans l'export CPU, sans rééchantillonnage horizontal.

## Étapes d'implémentation
1. Ajouter un module, par exemple `src/vector_text.rs`.
2. Dans ce module, centraliser:
   - résolution de la famille de police rythmo (`config.ui.rythmo_font` ou fallback sans-serif);
   - échappement XML du contenu texte et du nom de police;
   - création du SVG avec couleur blanche/opacité correcte;
   - rendu `resvg` vers `Pixmap` aux dimensions finales `dest_w x dest_h`;
   - calcul/retour des ratios de limites de caractères pour curseur/sélection, en conservant la mesure `glyphon` existante ou équivalente.
3. Remplacer `UiRenderer::rasterize_text`/`prepare_stretched_texts` pour les textes rythmo:
   - inclure dans la clé de cache le texte, la police, la taille finale arrondie et la taille de police logique;
   - ne plus dépendre uniquement de `line_id` et `text_hash`, sinon un redimensionnement réutiliserait une texture à mauvaise résolution;
   - utiliser une texture `Rgba8UnormSrgb` ou cohérente avec l'existant, et un sampler linéaire ou le sampler existant puisque le rendu doit être 1:1;
   - garder `cursor_x_ratio` et `cursor_pos_from_x_ratio` compatibles avec le cache par ligne.
4. Remplacer le rendu du texte principal dans `src/rythmo_gpu_renderer.rs`:
   - rendre chaque texte/segment directement à sa largeur finale avant upload;
   - inclure `font_size`, `dest_w`, `dest_h`, police et texte dans la clé `text_cache`;
   - pour les syllabes, éviter le découpage UV d'une texture complète étirée; rendre chaque segment dans sa largeur finale comme le fait l'UI.
5. Remplacer `CpuRenderer::blit_stretched_text` dans `src/rythmo_cpu_renderer.rs`:
   - produire la pixmap SVG à `dest_w x dest_h`;
   - alpha-blender cette pixmap dans la pixmap export;
   - si des ratios de syllabes sont enregistrés, rendre les segments séparément comme côté UI/GPU.
6. Conserver le rendu bitmap/glyphon actuel pour:
   - labels UI ordinaires;
   - noms de personnages/badges;
   - notes non étirées, sauf si la vérification montre aussi un défaut visible.
7. Nettoyer le code obsolète:
   - supprimer ou réduire les fonctions `rasterize_text` dédiées au texte rythmo si elles ne servent plus;
   - renommer les commentaires qui parlent de `Stretched Text` bitmap pour refléter le rendu SVG/vectoriel.

## Points d'attention
- Le résultat final est toujours rasterisé à l'écran/vidéo, mais la rasterisation se fait après l'étirement vectoriel, donc sans agrandir un bitmap basse résolution.
- `resvg` doit trouver la police système sélectionnée. Si une police configurée est absente, le fallback doit rester propre et ne pas planter.
- Les caractères spéciaux (`&`, `<`, `>`, guillemets, accents, flèches hors chemin texte) doivent être correctement échappés.
- Les caches doivent être invalidés quand la police change via les paramètres; `clear_text_cache` existe déjà côté UI.
- Les exports CPU et GPU doivent produire un rendu cohérent avec l'affichage interactif.

## Vérification
- Lancer `cargo check`.
- Tester visuellement dans l'app une ligne très courte étirée très large: les bords doivent rester lisses, sans gros pixels.
- Tester une ligne avec syllabes/ratios sauvegardés: les segments doivent rester nets et aux bonnes largeurs.
- Tester un export CPU et un export GPU si les deux chemins sont disponibles, à une résolution élevée.
- Tester une police rythmo personnalisée depuis les paramètres et le fallback par défaut.
